Como funciona a autenticação moderna

Resumo em pt-BR · vídeo ~19:51 · ver no YouTube · 30/08/2026
Você clica em "entrar" e em 200 ms está logado. Como o servidor sabe que você é quem diz ser? O vídeo percorre cada etapa da autenticação moderna — senhas com hash, sessões, JWT, OAuth/OIDC, MFA, passkeys — e os erros de segurança que causam problemas em produção.

0.Autenticação ≠ Autorização

Conceito-chave
Autenticação prova quem você é (mostra o documento na portaria). Autorização define o que você pode fazer (crachá que libera o andar). Primeiro prova a identidade, depois o sistema decide o que liberar.

1.Senha: hash + salt (+ erros comuns)

O servidor nunca deve guardar senha em texto — se o banco vazar, o atacante teria tudo.

  • Hash: transforma texto numa string fixa, processo irreversível (texto → hash, nunca o inverso)
  • SHA-256 é rápido demais: ~1 bilhão de hashes/s numa GPU moderna → atacante testa bilhões de senhas em segundos
  • bcrypt / Argon2 são lentos de propósito: usam work factor (nº de rodadas). Com valor certo, cada hash demora centenas de ms → ataque de segundos vira anos
  • Salt: valor aleatório antes do hash. Duas pessoas com a mesma senha geram hashes diferentes. Sem salt, atacante usa rainbow tables (tabelas pré-computadas de hashes comuns)
  • Login: servidor pega a senha digitada, aplica hash com o salt salvo e compara com o hash armazenado
Erros comuns
❌ Mensagens de erro diferentes ("usuário não encontrado" vs "senha incorreta") → atacante descobre quais e-mails existem. Sempre mensagem genérica: "e-mail ou senha incorretos".
❌ Sem rate limiting → script testa 100.000 senhas/min. Proteção: limitar por IP e por conta, bloqueio temporário após X falhas.
❌ SQL Injection no login: concatenar input na query. ' OR 1=1 -- no e-mail retorna todos os usuários. Solução: queries parametrizadas, nunca concatenar input do usuário.

2.Sessão: o servidor lembra do login

E-mail/senha → servidor valida → cria registro de sessão → devolve identificador num cookie que o browser guarda e envia automaticamente em toda requisição. O servidor confere na memória e sabe quem é você.

  • HttpOnly: JS não acessa o cookie → protege contra XSS
  • Secure: só envia por HTTPS
  • SameSite: bloqueia envio de outros domínios → protege contra CSRF
Cuidados
Session fixation: atacante planta um session ID antes do login; se o ID não muda após login, ele o usa. Solução: gerar novo session ID após o login.
Troca de senha: se o atacante já roubou a sessão, trocar a senha não resolve — é preciso invalidar todas as sessões e forçar login.
Onde guardar: memória (rápida, reiniciou perdeu) → banco (persistente, query extra) → Redis (padrão de produção: rápido, compartilhado entre servidores). Sem ele, com 3 servidores atrás de load balancer a sessão só existe num deles. Sessões são stateful, e estado é difícil de escalar.

3.JWT: autenticar sem estado

JWT = 3 partes separadas por ponto:

  • Header: algoritmo de assinatura
  • Payload: ID do usuário, expiração, escopos. Base64 → não é criptografado! Qualquer um com o token lê o conteúdo → nunca colocar dados sensíveis
  • Signature: garante que ninguém forjou o conteúdo

Algoritmos: HMAC (chave simétrica — a mesma que assina verifica; bom com 1 servidor) · RSA/ECDSA (assimétricas — privada assina, pública verifica; essencial em microsserviços: cada serviço só precisa da chave pública, a privada nunca sai do auth server).

Erros
❌ Chave secreta fraca ("secret123") → forja qualquer token. Chave: ≥ 256 bits de entropia, aleatória, em variável de ambiente.
❌ Verificar só a assinatura, ignorar issuer (iss) e audience (aud) → token do serviço A reutilizado no B. Valide sempre iss + aud + exp.

Fluxo: login → servidor gera token → devolve → cada requisição manda no header Authorization: Bearer <token> → servidor verifica a assinatura, sem guardar nada.

Onde guardar
❌ localStorage: JS lê e manda no header — mas qualquer script malicioso também lê (XSS) → token vaza.
✅ Cookie HttpOnly: JS não acessa, browser manda automaticamente. Regra: aplicação web → cookies.

Revogação: access token ~15 min + refresh token (dias/semanas) com rotação — cada uso invalida o antigo e gera novo. Se roubarem o antigo, já não funciona.

4.Sessão vs JWT

SituaçãoEscolha
App web tradicional, 1 servidor, poucos serviçosSessão — simples, fácil de revogar, servidor controla tudo
API consumida por vários clientes / microsserviçosJWT — cada serviço valida sozinho com a chave pública
Híbrido comumOs dois — sessão pro usuário final, JWT entre serviços internos

Sessão = simplicidade + revogação · JWT = escala + flexibilidade.

5.OAuth 2.0: "entrar com Google"

OAuth é autorização delegada: você autoriza um app a acessar seus dados em outro serviço sem dar sua senha. O app nunca vê sua senha do Google; só recebe permissão para nome e e-mail.

4 papéis: Resource Owner (você) · Client (o app) · Authorization Server (quem autentica/autoriza — ex.: Google) · Resource Server (a API com os dados).

Fluxo mais seguro — Authorization Code
1. App redireciona pro Google com: client ID, URL de retorno, escopos e state aleatório (anti-CSRF)
2. Você loga no Google, vê a tela de permissões, aceita
3. Google redireciona de volta com código de autorização na URL (uso único, vida curta)
4. App manda o código pro Google direto do back end + client secret → recebe os tokens (servidor-a-servidor; o token nunca passa pelo browser)

Exceção: apps mobile — não têm como guardar client secret (qualquer um inspeciona o código). Solução: PKCE: app gera string aleatória (code verifier) → calcula o hash (code challenge) e manda na 1ª requisição → ao trocar código por tokens, manda o verifier; o Google aplica o hash e compara. Se bater, prova que quem troca é quem iniciou o fluxo. Mesmo interceptando o código, sem verifier não troca por tokens.

Erros
❌ Open redirect: se o authorization server não valida a redirect URI exatamente (caráter por caráter, sem wildcard), o atacante aponta pro domínio dele e o código cai no servidor dele.
❌ Sem state: atacante inicia fluxo OAuth com a conta dele e manda o callback pra vítima → vincula a conta do atacante ao perfil da vítima. State: sempre aleatório, vinculado à sessão, verificado no retorno.

6.OpenID Connect: identidade sobre OAuth

OAuth diz o que o app pode acessar, mas não quem é o usuário. OIDC adiciona o ID token — um JWT com identidade (nome, e-mail, foto). "Entrar com Google" na prática é OIDC.

  • Nonce: valor único por login; protege contra replay (atacante copia o token da rede e reenvia; o servidor vê que já foi usado e rejeita)
  • Escopos: definem exatamente o que o app pode fazer (ler e-mail, não deletar). Menor privilégio: o app só recebe o menor escopo necessário, escopos ficam no token, a API checa antes de responder — sem o escopo certo, nega mesmo com token válido

7.MFA: segunda camada de defesa

3 fatores: algo que você sabe (senha/PIN) · algo que você tem (celular/chave física) · algo que você é (digital/facial). MFA exige pelo menos 2 fatores diferentes.

  • SMS: o mais fraco — número clonável por SIM swap
  • TOTP: servidor gera chave secreta compartilhada com o app (Google Authenticator, 1Password); o app combina chave + horário/30s e aplica HMAC → código de 6 dígitos a cada 30s; servidor faz a mesma conta; sem internet. Vulnerável a phishing (código digitado em site falso)
  • Chaves físicas (U2F): não vulneráveis a phishing
Atenção
MFA só no login não basta: se o atacante já tem sessão ativa, pode trocar e-mail, resetar senha e tomar a conta. Operações sensíveis (trocar e-mail, mudar senha, desativar MFA, transferir dinheiro) exigem step-up authentication — pedir o 2º fator de novo.

8.Passkeys: eliminar a senha

Passkeys (WebAuthn/FIDO2) eliminam senhas com criptografia de chave pública:

  • Dispositivo gera par de chaves → chave privada fica no dispositivo (protegida por biometria/PIN, nunca sai dele) → chave pública vai pro servidor
  • Login: servidor manda challenge aleatório → dispositivo pede biometria, assina → servidor verifica com a pública. Sem senha, sem código, sem nada roubável por phishing
  • Anti-phishing nativo: chave vinculada ao domínio — site falso não funciona ("gooogle.com" não é reconhecido)
  • Podem ser sincronizadas (iCloud Keychain, Google Password Manager) — resolve perder o celular, adiciona confiança na nuvem; para alta segurança, passkeys não sincronizadas em hardware (YubiKey)

9.Os 3 ataques mais comuns + password reset

  • XSS: injeta JS malicioso na página; token no localStorage vaza. Defesa em camadas: cookie HttpOnly + CSP + sanitização de input
  • CSRF: site do atacante faz requisição pro seu banco; cookies são enviados automaticamente. SameSite=Strict resolve a maioria; formulários: token CSRF único por sessão
  • CORS mal configurado: Access-Control-Allow-Origin: * + credentials: true → qualquer site faz requisições autenticadas. Correção: origens explícitas
  • Password reset: token previsível (base64 do ID) → tokens pra qualquer conta. Token: aleatório, expira em minutos, uso único, e invalidar todas as sessões após resetar

10.Fluxo completo

1. Usuário digita e-mail e senha · 2. Servidor compara o hash (bcrypt), confere o salt · 3. Pede o 2º fator (TOTP ou passkey assina o challenge) · 4. Gera access token JWT de 15 min (chave privada) + refresh token com rotação · 5. A cada requisição, a API verifica assinatura, checa escopos e responde · 6. Access expira → refresh renova nos bastidores · 7. Login social → OAuth com PKCE + OIDC traz a identidade no ID token.

11.Exemplos de código — Java 26, Go 1.26 e Python 3.14

Implementações com stdlib pura (sem dependências), validadas: os 9 exemplos compilam e rodam; o TOTP produz o mesmo código (935084) nas 3 linguagens no mesmo segundo.

Hash de senha (PBKDF2)

// Java 26 — Hash com PBKDF2 (javax.crypto)
import javax.crypto.SecretKeyFactory;
import javax.crypto.spec.PBEKeySpec;
import java.security.SecureRandom;
import java.util.HexFormat;

public class PasswordHash {
    public static void main(String[] args) throws Exception {
        char[] senha = "minha-senha".toCharArray();
        byte[] salt = new byte[16];
        new SecureRandom().nextBytes(salt);

        // Work factor alto: 600.000 iteracoes, 256 bits
        PBEKeySpec spec = new PBEKeySpec(senha, salt, 600_000, 256);
        SecretKeyFactory f =
            SecretKeyFactory.getInstance("PBKDF2WithHmacSHA256");
        byte[] hash = f.generateSecret(spec).getEncoded();

        // Armazenar salt + hash + iteracoes (nunca a senha)
        System.out.println("salt: " + HexFormat.of().formatHex(salt));
        System.out.println("hash: " + HexFormat.of().formatHex(hash));
    }
}

// Go 1.26 — Hash com PBKDF2 (crypto/pbkdf2)
package main

import (
    "crypto/pbkdf2"
    "crypto/rand"
    "crypto/sha256"
    "encoding/hex"
    "fmt"
)

func main() {
    salt := make([]byte, 16)
    rand.Read(salt)

    // Work factor alto: 600.000 iteracoes, 32 bytes
    // Key(h func() Hash, password string, salt, iter, keyLen)
    hash, err := pbkdf2.Key(sha256.New, "minha-senha",
        salt, 600_000, 32)
    if err != nil {
        panic(err)
    }

    // Armazenar salt + hash + iteracoes (nunca a senha)
    fmt.Println("salt:", hex.EncodeToString(salt))
    fmt.Println("hash:", hex.EncodeToString(hash))
}

# Python 3.14 — Hash com PBKDF2 (hashlib)
import hashlib
import os


def hash_senha(senha: str, iteracoes: int = 600_000):
    salt = os.urandom(16)  # salt aleatorio por usuario

    # Work factor alto: 600.000 iteracoes
    hash_bytes = hashlib.pbkdf2_hmac(
        "sha256", senha.encode(), salt, iteracoes
    )

    # Armazenar salt + hash + iteracoes (nunca a senha)
    return salt.hex(), hash_bytes.hex()


if __name__ == "__main__":
    salt, h = hash_senha("minha-senha")
    print(f"salt: {salt}")
    print(f"hash: {h}")

Assinatura de token (JWT HS256)

// Java 26 — JWT HS256 (HMAC-SHA256)
import javax.crypto.Mac;
import javax.crypto.spec.SecretKeySpec;
import java.nio.charset.StandardCharsets;
import java.util.Base64;

public class JwtHmac {
    static String b64url(byte[] b) {
        return Base64.getUrlEncoder()
            .withoutPadding().encodeToString(b);
    }

    static byte[] hmac(String secret, String data)
        throws Exception {
        Mac mac = Mac.getInstance("HmacSHA256");
        mac.init(new SecretKeySpec(
            secret.getBytes(StandardCharsets.UTF_8),
            "HmacSHA256"));
        return mac.doFinal(
            data.getBytes(StandardCharsets.UTF_8));
    }

    public static void main(String[] args)
        throws Exception {
        String secret =
            "chave-com-256-bits-de-entropia!!";

        // Header/payload base64url (NAO criptografado)
        String header =
            "{\"alg\":\"HS256\",\"typ\":\"JWT\"}";
        String payload =
            "{\"sub\":\"42\",\"exp\":1750000000,"
            + "\"scope\":\"read\"}";
        String signingInput = b64url(header.getBytes())
            + "." + b64url(payload.getBytes());
        String signature =
            b64url(hmac(secret, signingInput));

        String token = signingInput + "." + signature;
        System.out.println("token: " + token);

        // Verificacao: recalcula e compara
        String expected =
            b64url(hmac(secret, signingInput));
        System.out.println("assinatura valida: "
            + expected.equals(signature));
    }
}

// Go 1.26 — JWT HS256 (HMAC-SHA256)
package main

import (
    "crypto/hmac"
    "crypto/sha256"
    "encoding/base64"
    "encoding/json"
    "fmt"
)

func b64url(b []byte) string {
    return base64.RawURLEncoding.EncodeToString(b)
}

func main() {
    // Variavel de ambiente na vida real
    secret := []byte(
        "chave-com-256-bits-de-entropia!!")

    // Header/payload base64url (NAO criptografado)
    header, _ := json.Marshal(
        map[string]string{
            "alg": "HS256", "typ": "JWT"})
    payload, _ := json.Marshal(
        map[string]any{
            "sub": "42", "exp": 1750000000,
            "scope": "read"})

    signingInput := b64url(header) + "." + b64url(payload)

    mac := hmac.New(sha256.New, secret)
    mac.Write([]byte(signingInput))
    signature := b64url(mac.Sum(nil))

    token := signingInput + "." + signature
    fmt.Println("token:", token)

    // Verificacao: recalcula e compara
    mac2 := hmac.New(sha256.New, secret)
    mac2.Write([]byte(signingInput))
    fmt.Println("assinatura valida:",
        hmac.Equal(mac2.Sum(nil),
            mustDecode(signature)))
}

func mustDecode(s string) []byte {
    b, err := base64.RawURLEncoding.DecodeString(s)
    if err != nil {
        panic(err)
    }
    return b
}

# Python 3.14 — JWT HS256 (HMAC-SHA256)
import base64
import hashlib
import hmac
import json


def b64url(data: bytes) -> str:
    return base64.urlsafe_b64encode(
        data).rstrip(b"=").decode()


def assinar_jwt(payload: dict, secret: str) -> str:
    header = {"alg": "HS256",
              "typ": "JWT"}

    # Header/payload base64url (NAO criptografado)
    enc = lambda d: b64url(json.dumps(
        d, separators=(",", ":")).encode())
    signing_input = enc(header) + "." + enc(payload)

    # Assina: HMAC-SHA256
    sig = hmac.new(secret.encode(),
        signing_input.encode(), hashlib.sha256).digest()
    return signing_input + "." + b64url(sig)


def verificar_jwt(token: str, secret: str) -> bool:
    signing_input, _, sig = token.rpartition(".")
    expected = hmac.new(secret.encode(),
        signing_input.encode(),
        hashlib.sha256).digest()
    return hmac.compare_digest(
        b64url(expected).encode(), sig.encode())


if __name__ == "__main__":
    secret = "chave-com-256-bits-de-entropia!!"
    token = assinar_jwt(
        {"sub": "42", "exp": 1750000000,
         "scope": "read"}, secret)
    print(f"token: {token}")
    print("assinatura valida:",
        verificar_jwt(token, secret))

TOTP — código de 6 dígitos (RFC 6238)

// Java 26 — TOTP (RFC 6238)
import javax.crypto.Mac;
import javax.crypto.spec.SecretKeySpec;
import java.nio.ByteBuffer;
import java.nio.charset.StandardCharsets;

public class Totp {
    static String totp(String secret,
        long nowSeconds) throws Exception {
        // Janela de 30 segundos
        long counter = nowSeconds / 30;
        byte[] msg = ByteBuffer.allocate(8)
            .putLong(counter).array();

        Mac mac = Mac.getInstance("HmacSHA1");
        mac.init(new SecretKeySpec(
            secret.getBytes(StandardCharsets.UTF_8),
            "HmacSHA1"));
        byte[] h = mac.doFinal(msg);

        // Dynamic truncation (RFC 4226)
        int offset = h[h.length - 1] & 0x0F;
        int code = ((h[offset] & 0x7F) << 24)
            | ((h[offset + 1] & 0xFF) << 16)
            | ((h[offset + 2] & 0xFF) << 8)
            | (h[offset + 3] & 0xFF);
        return String.format("%06d",
            code % 1_000_000);
    }

    public static void main(String[] args)
        throws Exception {
        long now =
            System.currentTimeMillis() / 1000;
        System.out.println("codigo atual: "
            + totp("chave-secreta-compartilhada",
                now));
    }
}

// Go 1.26 — TOTP (RFC 6238)
package main

import (
    "crypto/hmac"
    "crypto/sha1"
    "encoding/binary"
    "fmt"
    "time"
)

func totp(secret string, now time.Time) string {
    // Janela de 30 segundos
    counter := uint64(now.Unix() / 30)
    var msg [8]byte
    binary.BigEndian.PutUint64(msg[:], counter)

    mac := hmac.New(sha1.New, []byte(secret))
    mac.Write(msg[:])
    h := mac.Sum(nil)

    // Dynamic truncation (RFC 4226)
    offset := h[len(h)-1] & 0x0F
    code := (int(h[offset])&0x7F)<<24 | int(h[offset+1])<<16 | int(h[offset+2])<<8 | int(h[offset+3])
    return fmt.Sprintf("%06d",
        code%1_000_000)
}

func main() {
    fmt.Println("codigo atual:",
        totp("chave-secreta-compartilhada",
            time.Now()))
}

# Python 3.14 — TOTP (RFC 6238)
import hashlib
import hmac
import struct
import time


def totp(secret: str,
          now: int | None = None) -> str:
    now = int(time.time()) if now is None else now
    counter = now // 30  # janela de 30s

    # HMAC-SHA1 sobre o contador big-endian (8B)
    msg = struct.pack(">Q", counter)
    h = hmac.new(secret.encode(), msg,
                 hashlib.sha1).digest()

    # Dynamic truncation (RFC 4226)
    offset = h[-1] & 0x0F
    code = (struct.unpack(">I",
        h[offset:offset + 4])[0] & 0x7FFFFFFF) \
        % 1_000_000
    return f"{code:06d}"


if __name__ == "__main__":
    print(f"codigo atual: "
          f"{totp('chave-secreta-compartilhada')}")

12.Checklist de segurança

  • Senha: hash lento (bcrypt/Argon2/PBKDF2) + salt único por usuário
  • Mensagem de login genérica ("e-mail ou senha incorretos")
  • Rate limiting por IP e por conta
  • Queries parametrizadas (nunca concatenar input)
  • Cookie: HttpOnly + Secure + SameSite; novo session ID após login
  • Invalidar todas as sessões ao trocar senha
  • Sessão em Redis (não em memória de servidor único)
  • JWT: secret ≥ 256 bits em env var; validar iss + aud + exp; sem dados sensíveis no payload
  • Token em cookie HttpOnly (não localStorage)
  • Access token curto (~15 min) + refresh token com rotação
  • OAuth: Authorization Code + PKCE (mobile), redirect URI exata, state anti-CSRF
  • OIDC: validar nonce (anti-replay)
  • MFA: TOTP ou chave física (não SMS); step-up em operações sensíveis
  • Passkeys onde possível (anti-phishing nativo)
  • CSP + sanitização (anti-XSS); SameSite=Strict + token CSRF (anti-CSRF)
  • CORS: origens explícitas, nunca * com credentials
  • Password reset: token aleatório, expira em minutos, uso único, invalidar sessões
